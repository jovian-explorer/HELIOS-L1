# Changelog

## Unreleased

### Security
- Cross-site requests to the local server. The server allowed every origin with credentials (CORS `*`), so any web page open in the user's browser could read every API answer and, after the preflight it approved, send JSON POSTs to `127.0.0.1:8765` that changed and saved the settings or replaced the imported dataset; `<img>` or link requests from any site could start month-long archive downloads; and a site whose name resolves to 127.0.0.1 (DNS rebinding) was treated as the server itself. The CORS middleware is gone (the interface is served by the server itself) and a request guard now rejects, before routing: requests whose Host is not 127.0.0.1, localhost or [::1] (403), API requests the browser marks as cross-site or same-site from another port (`Sec-Fetch-Site`) or that carry another `Origin` (403), and POST/PUT/PATCH/DELETE without `Content-Type: application/json` (415), so the form and text/plain bodies a page can send without a preflight never reach an endpoint. Scripts and `curl` (no browser headers) work as before; the interface was checked in Chromium (settings, import, CSV download), and a page on another origin can no longer change the settings.
- Download file names. The export of an imported dataset named its file after the mission name typed in the import tab, unchanged: path separators (`..\..\AppData\...`) and quotes reached the browser's save dialog, a CR/LF in the name injected a response header, and a name outside Latin-1 (e.g. Japanese) made the export fail with a 500. Every download name (exports, reports, analysis JSON, archive and epoch CSV) is now reduced to ASCII letters, digits, `.`, `_` and `-` and quoted. No request value is used as a path on the server: the cache file names come from dataset IDs and hashes, and static files stay inside the static folder (checked with encoded `..` and backslash paths).
- Request limits. Request bodies had no size limit (a 70 MB import was read, decoded and parsed whole), the superposed epoch analysis accepted 60 onsets with 240-hour windows, i.e. 600 days of OMNI files in one request, and the ephemeris endpoint computed every entry of an arbitrarily long, repeated spacecraft list. Imports are now limited to 64 MB and every other POST body to 64 kB (413, counted also for chunked bodies), the mission name to 200 characters, the epoch analysis to 180 days of data in total (events × window, e.g. 60 events of 72 h), and ephemeris requests to 40 distinct spacecraft (repeats are dropped). The import tab says so before reading a file larger than about 60 MB.
- Error answers. A sweep of every GET endpoint with malformed values found 500s: `nan`, `inf` or `1e309` in any numeric query parameter (orbits, ephemeris, Parker spiral, GIC, D-RAP) passed validation and failed JSON encoding, an empty `epoch=` failed in the ephemeris engine, and NaN/Infinity in a JSON body (Python's parser accepts them) made FastAPI's own 422 handler fail. Non-finite numbers now answer 422 naming the parameter, the 422 handler reports the offending input as text, and an empty epoch means now. The CME solver answered 200 with an `error` field for Δt = 0 or r2 ≤ r1, accepted negative drag and any wind speed, and replaced an unreadable launch time by the current time without a word; it now answers 422 for all of these (heights 1-300 R☉, Δt up to 7 days, wind 100-1500 km/s, drag above 0). Saving the settings when the file cannot be written (read-only profile, locked file) still applies them for the session, but the answer now says `"saved": false` with the reason and the settings dialog shows it; it reported `"saved": true` whenever an older settings file existed.
- Bind address and port. `--host` accepted any address, so `helios --host 0.0.0.0` served the API (settings, imports) to the local network; the launcher now refuses anything but 127.0.0.1, localhost or ::1 with a clear message (exit code 2). When the chosen port was taken by another program between the free-port check and the start, the server thread died silently, the launcher saw something answering on the port, printed "Engine online" and opened the window on the other program; it now waits for its own server to report that it is listening and otherwise stops with "could not listen on 127.0.0.1:<port>: the port is in use by another program ... start HELIOS-L1 with --port <a free port>" and the system's reason (exit code 1). The launcher works with `--host ::1` too.
- Stored script injection in the desktop window. The name of an imported dataset (the file name, or the name typed in the import tab) went unescaped into the HTML of the mission directory, so a file named `<img src=x onerror=...>.csv` (a valid name on macOS and Linux), or an import posted by another web site under the old CORS policy, ran script inside the application, where the request guard cannot help. The mission cards now escape every text field, as do the reference search text and the server error messages shown in the timing panel, the fleet matrix, the bulletin and the reference library. Checked in Chromium: the payload ran before the change and shows as text after it.

### Statistics and uncertainties
- Ring current model skill with 95 % intervals. The scores of the Burton and O'Brien-McPherron models against Kyoto Dst (live view) and SYM-H (events, `/api/storm/indices`) now carry intervals for r, RMSE and bias that allow for the autocorrelation of the series: an effective sample size from the lag-1 autocorrelations (Bretherton et al. 1999, eq. 31, for r with the Fisher z interval; Wilks 2011, eq. 5.12, with Student's t for the bias and the mean squared error, the latter on a log scale). Treating every 5-minute sample as independent gave intervals several times too narrow: for 10-12 May 2024 the 864 samples are worth about 3 independent ones, so the answer says that one storm is too few to bound r and gives wide RMSE and bias intervals (O'Brien-McPherron RMSE 64.9 nT, 38-111). The Fisher intervals match scipy's `pearsonr` to 1e-6; simulated AR(1) series (lag-1 autocorrelation 0, 0.5, 0.9) give coverages of 94-96 %, 93-94 % and 90-94 %, and the answer flags fewer than 10 independent samples, where the AR(1) estimate makes intervals too narrow. New module `helios/core/statistics.py`.
- Cross-correlation lag between two spacecraft with a 95 % interval and standard deviation: a moving-block bootstrap (Künsch 1989) resamples blocks of consecutive samples of the lagged products a[n]·b[n+L], re-evaluates every lag on the same resample and finds the peak again (500 resamples, blocks as long as the decorrelation length of the pair and at least the largest lag). In simulations of noisy AR(1) signals with a known 15-minute delay the interval covered the delay in 99-100 % of 200 trials per case, with a bootstrap spread 1.3-1.6 times the actual spread of the estimate, so it is conservative. The comparator's Pearson r now has a 95 % interval as well (Fisher z with the effective sample size of the two series). Both are shown under the values in the comparison tab.
- OMNI statistics (`/api/statistics/omni`, new module `helios/core/omni_statistics.py`): hourly OMNI (OMNI2_H0_MRG1HR, 1963 to the present, one HAPI request per year, cached) with distributions, joint histograms, conditional averages, correlations (Pearson with Fisher interval, and Spearman) and yearly or monthly statistics with the period's sunspot number and the correlation of the period means with it. Intervals use effective sample sizes from the lag-1 autocorrelation of consecutive selected hours (a gappy AR(1) series with 20 % of hours missing: 95 % interval coverage 90-99 % in 300 trials). Filters: conditions on any quantity, southward/northward IMF runs of at least N hours, solar wind type, fine-scale field and plasma points per hour (quality and coverage) and Dst thresholds; the answer, its provenance and the CSV header list every filter with the hours it kept. Derived per hour: Newell dΦ/dt, V·Bs, clock angle, Alfvén speed, specific entropy, Texp/T and the Xu & Borovsky (2015) type from their three planes (as in the FDL 2025 Heliolab code; within 0.5 % of the rounded published inequalities). Checks: daily means of the decoded hourly data equal NASA's published daily averages (omni_01_av.dat) for all 10 955 days of 1995-2024 within the file's rounding, and 27-day means match omni_27_av.dat within rounding for 95 % of 406 rotations (the rest differ by at most 0.1 units, because NASA averages its rounded daily values); 88.5 % of the OMNI hours inside the 106 magnetic clouds of the WIND MFI list (Lepping et al.) are classified as ejecta, against 87.5 % for the same scheme on the magnetic cloud reference set in Li et al. (2020, Earth Space Sci., arXiv:1811.02323), and 91 % of fast wind (V > 600 km/s) outside clouds as coronal-hole plasma. For 1995-2024 the mean speed is 425.8 km/s (95 % interval 419.7-431.9; about 1000 independent samples in 262 000 hours); yearly |B| ranges from 3.9 nT (2009) to 7.6 nT (2002, 2025), r = 0.79 (0.43-0.94) with the sunspot number.
- Ring current model skill over many storms (`/api/statistics/dst_models`, button next to *Find storms*): Burton (1975) and O'Brien-McPherron (2000) run over every hour of the selected years from hourly OMNI (never reset to the observations), scored in each storm window (from the highest Dst in the 24 h before the minimum to the recovery above -50 nT, after Ji et al. 2012), with the means of r, RMSE, bias and minimum error over the storms and Student-t 95 % intervals. Checked against Ji et al. (2012, JGR 117, A03209, Tables 2-3): with their 63 storm windows of 1998-2006, our O'Brien-McPherron gives per-group r of 0.90/0.84/0.87/0.89 (sMC/SH/CIR/non-MC; theirs 0.90/0.80/0.87/0.90) and RMSE 28.2/28.1/19.9/23.8 nT (theirs 26.5/27.6/19.0/20.2), and with our own windows over 84 storms r 0.88 (0.85-0.92) and RMSE 26.4 nT (21.9-31.0). Burton matches in r (0.89/0.78/0.81/0.89 against 0.89/0.71/0.77/0.88) but not in RMSE (57/41/27/41 against 51/56/48/39 nT) or the error of the minimum (-8 nT on average against about +60 nT): their Burton storms are weaker than ours, which use the injection and decay constants of Burton et al. (1975); their constants are not given, so this difference is left as it is and stated here.
- Storm selection by strength (`/api/statistics/storms`) feeding the superposed epoch analysis: runs of hourly Dst at or below a threshold, joined when Dst recovers above it for less than a given time (6 h by default, so that two-step main phases count once), with an optional floor (e.g. intense but not super storms), the plasma type before the minimum (Xu & Borovsky class most frequent in the preceding 6 h), and the mean Bz, speed and Newell coupling of those hours. `/api/analysis/superposed` accepts the same selection instead of onset times, at the Dst minimum or the first hour below the threshold, and writes the selection and its filters (with the storms each kept) into the provenance and the CSV header; the tab's *Find storms* form fills the onset list and keeps the selection while the list is unchanged. Checked against Echer et al.: 1996-2006 at -100 nT gives 90 storms (Echer et al. 2008, JGR 113, A05221: 90); at -250 nT the storms have minima from -263 to -422 nT as in Echer et al. (2008, GRL 35, L06S03), who count eleven where we find ten, the eleventh (15 May 2005, -263 nT in the data of the time) being -247 nT in today's final Dst. In 2015-2024 ten storms reach -150 nT. The plasma type is labelled as a plasma property: sheath and stream-interaction compressions often fall in the ejecta class (81 of the 90 storms of cycle 23), so it is not a driver catalogue.
- OMNI statistics panel in the Event Analysis tab: years, analysis, x and y, bins and log axes, and the filters (conditions, Bz runs, fine-scale points per hour, solar wind types) as form fields; a histogram, a heat map of the joint histogram, the conditional mean with its 95 % band and the quartiles, or the yearly/monthly means with their intervals next to the sunspot number; the correlation and every filter with the hours it kept below the chart, with CSV and JSON downloads. Five example buttons (Dst against the Newell coupling, |B| over the solar cycles, speed distribution, speed against temperature, Bz during intense storms).
- Flux rope fit uncertainties: 1σ errors of B0, R0 (and the diameter), the asymmetry factor, the closest approach, the axis latitude and the axis direction (error cone) from the error study of Lepping, Berdichevsky & Ferguson (2003, JGR 108(A10), 1356), which fitted 1824 simulated clouds noised up with fluctuations from real WIND clouds. The new module `helios/core/lepping_errors.py` ports the WIND MFI team's `interpolation_mc.pro` and its input table `sigcommon.pro` (wind.nasa.gov/mfi): noise level (155/8.3666)·χR, quadratic fits in the noise level, the program's final interpolation in closest approach and cone angle (kept as written), σB0 scaled by B0/16.4 nT. With the WIND table's χR, CA and axis it reproduces Table 5 of Lepping et al. (2006, Ann. Geophys. 24, 215) for 48 of its 50 clouds to the printed precision (the other two differ by 1° in one column at an integer boundary). Shown as ± in the flux rope panel, with a warning when χR, the cone angle or the closest approach lie outside the error study. Rejected before this: errors from the fit itself (linearised χ², residual block bootstrap, boundary shifts of ±1 h), which came out 2-5 times smaller than the published ones, as Lepping et al. (2003) found for random-noise estimates.
- Coupling functions with uncertainties (`/api/analysis/coupling`, Event Analysis tab): Newell dΦ/dt, Akasofu ε, V·Bs and the dynamic pressure on every plasma sample of a WIND, ACE or DSCOVR interval (field averaged over the sample and rotated to GSM), and their interval means with two uncertainties: the measurement error propagated to first order from the 1-σ speed and density uncertainties that the WIND SWE non-linear fits carry per spectrum (now requested with the data), and the 95 % sampling interval of the mean from the effective sample size. ACE and DSCOVR archives give no per-sample uncertainties, so only the sampling interval is shown for them, and field uncertainties are in none of the archives. Checked against an independent recomputation of the four functions and against Monte Carlo draws from the archive errors (within 5 %) on WIND data of 17 March 2015; over that day the measurement error of each mean is about 0.3-0.6 % of the mean, the sampling interval about ±30-50 %.

### Event analysis
- ICME catalogue cross-matching (`helios/core/icme_catalog.py`, `GET /api/catalogs/icme`, a panel in Event Analysis): the Richardson & Cane list of near-Earth ICMEs since 1996 (I. G. Richardson and H. V. Cane, izw1.caltech.edu; also on Harvard Dataverse, doi:10.7910/DVN/C2MHTH, licence CC0 1.0, which the authors ask to be cited with Cane & Richardson 2003, JGR 108, 1156, and Richardson & Cane 2010, Sol. Phys. 264, 189). The live page is read when possible (cached for a week), otherwise a bundled snapshot of the July 23, 2026 revision (`scripts/update_icme_catalog.py` refreshes it); the answer says which. The storm finder marks each storm whose Dst minimum lies in a listed ICME, its sheath or the 3 h after it; magnetic cloud candidates list the ICMEs they overlap; a shock analysed at L1 names the listed disturbance 1 h before to 3 h after it (17 March 2015: the sudden commencement 45 min after the WIND shock). Checks: all 644 events agree with the authors' Dataverse spreadsheet of the same revision in disturbance, start, end, magnetic cloud flag and Dst (one spreadsheet cell, `0 P`, became a time in Excel); 1996-2002 holds 220 ICMEs (214 in Cane & Richardson 2003, before later revisions) and 1996-2009 holds 323 (about 300 in Richardson & Cane 2010); 89 of the 98 WIND magnetic clouds since 1996 (Lepping et al., wind.nasa.gov) lie inside a listed ICME, all of them flagged as magnetic clouds; for the 514 ICMEs with final Dst, the minimum OMNI hourly Dst from the disturbance to the ICME end (or the next disturbance) plus 1 h equals the listed value for 79 % and is within 2 nT for 90 %, the differences being the authors' attributions where ICMEs overlap or Dst was already depressed. Of the 90 intense storms of 1996-2006 (Echer et al. 2008), 75 fall in a listed ICME (57), its sheath (14) or just after it (4); all ten below -250 nT do.
- Interplanetary shock analysis on archive data at the instruments' own cadence (WIND MFI 3-s with SWE non-linear proton fits, ACE MAG 16-s with SWEPAM 64-s Level 2, DSCOVR MAG 1-s with the Faraday cup), not the 1-minute display means: shock normals from magnetic and velocity coplanarity and the three mixed-mode methods (MC, VC, MX1-3; Schwartz 1998, Abraham-Shrauner 1972), the shock speed from mass flux conservation, theta_Bn, density and field jumps, the upstream normal flow speed and Alfvén and fast Mach numbers, with uncertainties from Monte Carlo draws of the window means. The shock time can be refined to the largest |B| jump, the type (FF/FR/SF/SR) follows from the jumps, and the result carries warnings when the jump or the sample count is too small. Checked against the Harvard-Smithsonian CfA Interplanetary Shock Database: for the 17 March 2015 shock at WIND the MX3 normal is within 1° of the published one, theta_Bn 60.5° (CfA 60.1 ± 3.1°), shock speed 540 km/s (536 ± 3 km/s), compression 2.48 (2.45 ± 0.46), arrival within 3 s of the published time; for 27 February 2014 the normal is within 1° of the CfA MX3 normal, theta_Bn 78.7° (79.9 ± 3.8°), 439 km/s (436 km/s), arrival within 3 s; for 22 June 2015 the normal is 2.5° from the CfA's selected Rankine-Hugoniot normal, theta_Bn 63.3° (63.8 ± 5.0°) and the speed 762 km/s (median of the CfA methods 791 km/s). `GET /api/analysis/shock?mission=&time=&upstream_minutes=&downstream_minutes=&exclude_minutes=`.
- Shock analysis details: WIND SWE spectra flagged "poor peak identification" (fit_flag 1) are used and counted in a warning. Behind strong shocks most spectra carry this flag (all downstream spectra of 27 February 2014 and 6 September 2017), and the CfA database, built by the SWE team, uses them: its downstream values are those of the flagged spectra. The refined shock time is where |B| crosses half-way between the levels before and after the jump, not the largest difference of the 1-minute means, which could fall on the overshoot (ACE, 22 June 2015: 17:59:37 instead of 18:00:09). The "poorly constrained normal" warning compares MX3 with the other methods that use the velocity jump; magnetic coplanarity alone degenerates for quasi-perpendicular shocks (the CfA MC normal of 27 February 2014 is 70° from their MX3 too).
- Minimum variance analysis of the magnetic field for any interval of up to 72 h, with the eigenvalues, eigenvectors, eigenvalue ratios and the angular errors of Sonnerup & Scheible (1998, eq. 8.23): `GET /api/analysis/mva?mission=&start=&end=&average_seconds=`.
- Multi-spacecraft timing between WIND, ACE and DSCOVR: the shock normal and speed found at one spacecraft predict the arrival at the others from their measured positions, t = t_ref + n·Δr/V_sh, and the observed arrival (the |B| ramp near the prediction), the residual and the speed along n implied by the observed delay show whether the shock is planar over the baseline. Positions come from the WIND MFI file's definitive orbit (the SWE file gives positions to 1 R_E and the predicted WIND orbit file differed by 2 R_E), ACE MAG Level 2 and the DSCOVR orbit file. On 27 February 2014 ACE, 10 R_E further upstream than WIND but 140 R_E away in Y, saw the shock 17 minutes after WIND: the WIND normal predicts a 1016 s delay (1028 s from the CfA database's own normal, speed and positions), the ACE ramp is observed 1103 s after WIND, within the CfA ACE database's arrival time and its ±80 s, and the ACE position agrees with the CfA's to 0.04 R_E. `GET /api/analysis/timing?reference=WIND&time=&targets=ACE,DSCOVR`.
- Magnetic cloud flux rope fit: the force-free Lundquist model (B = B0 [J0(αr) axial + H J1(αr) azimuthal], αR0 = 2.405) is fitted to the field directions of 30-minute averages for the axis direction, closest approach and its time, for both handedness signs, with B0 from the full vectors and R0 from the duration and measured speed (Lepping et al. 1990). Checked against three quality-1 clouds of the WIND MFI magnetic cloud table with the table's boundaries: 18-20 October 1995 axis 9° from the published one, B0 24.4 nT (25.9), right-handed, closest approach 9 % (12 %), diameter 0.271 AU (0.257), axial flux 13.7×10²⁰ Mx (13.1), χR 0.149 (0.143); 10-11 January 1997 axis 13° off, B0 16.9 nT (17.7); 4-6 March 1998 axis 18° off, B0 12.6 nT (12.4), left-handed as listed. `GET /api/analysis/fluxrope?mission=WIND&start=&end=&average_minutes=30`.
- Superposed epoch analysis: 95 % bootstrap confidence intervals of the mean (and of the median for grids of up to 300 000 values) in every epoch bin with at least 3 events, from 1000 resamples of the events with replacement, in the JSON answer, the CSV table (`*_mean_ci95_low` ... columns) and as a band around the mean in the chart. Checked on synthetic events: for 40 events with a 10 nT scatter the interval width is the expected 2 × 1.96 × 10/√40 nT within 15 %.
- deHoffmann-Teller analysis (Khrabrov & Sonnerup 1998, ISSI SR-001 ch. 9): the frame velocity V_HT that minimises the mean square convection electric field (eq. 9.10) and, as a second estimate, the cross-field velocity (eq. 9.14), the frame quality (correlation of -v×B with -V_HT×B and D(V_HT)/D(0)), the error ellipsoid of eq. 9.16 and its bootstrap counterpart (1000 resamples of the vector pairs), the normal velocity u_n along the minimum variance normal of the same interval, and the Walén slope of v - V_HT against the proton Alfvén velocity (near ±1 for a rotational, near 0 for a tangential discontinuity). The field is averaged over each plasma sample. Checked against the AMPTE/IRM benchmark (Table 8.4 data): c = 0.994 and D(V_HT)/D(0) = 0.012 as published, error semiaxes 7.54, 4.54, 3.90 km/s (published 7.62, 4.59, 3.94), u_n error 3.9 km/s (3.9), bootstrap semiaxes 7.90, 5.07, 4.61 km/s (7.88, 5.29, 4.62 from another 5000 resamples), Walén slope 0.02 for this tangential discontinuity; V_HT = (-122.6, -223.6, 75.7) km/s against the published (-122.8, -223.0, 76.0), the difference coming from the one-decimal rounding of the published velocities (the same table reproduces the chapter 8 field results exactly). `GET /api/analysis/ht?mission=&start=&end=`; the minimum variance panel has a deHoffmann-Teller button for the same interval.
- Minimum variance analysis errors, checked against the benchmark of Sonnerup & Scheible (1998, ISSI SR-001, ch. 8), whose Table 8.4 lists the 16 AMPTE/IRM field vectors of the 19 October 1984 magnetopause crossing: eigenvalues 1012.86, 137.91 (published 138.01, from the rounded table values) and 7.08 nT², x3 = (0.8671, -0.4978, 0.0187) to four decimals, and the eq. 8.23 angular errors 0.062, 0.022 and 0.027 rad as published. The labels of these errors were swapped in the answer and the tab: the error of the rotation of the normal toward the intermediate eigenvector (about the maximum one) was shown as "about intermediate". The keys are now `normal_toward_intermediate`, `normal_toward_max` and `max_toward_intermediate`. New: the uncertainty of the normal field component from eq. 8.24 (1.63 nT for the benchmark, as published), the mean field along each eigenvector, and bootstrap errors (Kawano & Higuchi 1995) from 1000 resamples of the vectors: spread of <B>·n and of the rotations of the normal toward x1 and x2, and the bootstrap mean normal (benchmark 1.06 nT, 0.024 and 0.058 rad, published 1.17 nT, 0.023 and 0.059 rad from another 1000 resamples). The bootstrap is limited to 5 million resampled vectors in all; for longer native-cadence intervals the answer says to average the data first.
- Magnetic cloud search: the automatic identification scheme of Lepping, Wu & Berdichevsky (2005, Ann. Geophys. 23, 2687) on 1-minute archive data for up to 31 days. Running 25-min windows (30 min for the strict set) must have a mean proton beta of at most 0.3 and a smooth field latitude (chi^2 of a quadratic fit at most 500 deg^2, 450 strict); runs of such windows lasting at least 8 h are candidates, kept when the mean |B| is at least 7 nT (8), the mean proton thermal speed in the central third (whole region) at most 30 km/s, the field latitude spans at least 35 deg (45) and the large-scale smoothness chi_M/<B> of 15-min averages is at most 0.42, the values of the paper's Table 4 and Sect. 4.3. One addition, stated in the answer: a failing stretch no longer than one window does not end a region (the paper gives no rule; on 1-minute WIND data a single noisy minute otherwise splits most clouds into pieces shorter than 8 h), and windows need plasma for half their minutes (WIND SWE spectra come every 92 s). Checked against the WIND MFI magnetic cloud table over 1995 and 1997: with the loose set the search finds 18 of the 25 listed clouds (23 of them last 8 h or more), 15 with the front boundary within 6 h, and 8 regions that are not in the table; Lepping et al. report 88 % of the listed clouds and about twice as many cloud-like regions. For 7-8 November 1997 both listed clouds are found with front boundaries within 15 min and rear boundaries within 20 min of the table. The Event Analysis tab has a search panel whose candidates can be passed to the flux rope fit with one click. `GET /api/analysis/mcdetect?mission=WIND&start=&end=&criteria=loose`.
- Superposed epoch analysis of OMNI 1-min data keyed on any list of onset times (up to 60, e.g. sudden commencements or shock arrivals): SYM-H, ASY-H, AE, AL, AU, IMF, speed, density, temperature, dynamic pressure and ε on a common epoch grid with mean, median, quartiles and the number of events per bin, the per-event series, and each event's extremes with their epoch times. Checked on the sudden commencements of 17 March 2015 and 10 May 2024: the per-event SYM-H minima are the published -234 nT at 22:47 UT and -518 nT at 02:14 UT (Tulasi Ram et al. 2024) at epoch +18.03 h and +9.15 h, and SYM-H jumps by more than 40 nT within 5 minutes of epoch zero. `GET /api/analysis/superposed?onsets=2015-03-17T04:45,2024-05-10T17:05&parameters=sym_h,bz_gsm,speed&before_hours=12&after_hours=48&cadence_minutes=10` (`format=csv` for the table with a metadata header).
- Event Analysis tab (Data Studio & Science): forms for the shock analysis and multi-spacecraft timing, minimum variance analysis, the flux rope fit and the superposed epoch analysis, with the methods table, the field and density around the shock with the averaging windows marked, observed and model field of the flux rope, the epoch median, mean and quartile band per quantity, and links to save each result as JSON (and the epoch table as CSV). Buttons load the CfA-checked shocks of 17 March 2015, 27 February 2014 and 22 June 2015; the other fields start at the checked magnetic cloud and storms. Times are entered and shown in UTC. Checked in the browser (Playwright) against the live CDAWeb server: every panel returns the values listed above, server errors such as an unreadable time are shown as text, and the tab fits a 420 px wide window. A timing target without any data for the interval (DSCOVR before 2015) is reported as such instead of "no position".
- The answers include a provenance block (CDAWeb datasets with the exact HAPI requests, sample counts and coverage, method, parameters, software version, retrieval time) and are available as a JSON file with `download=true`.

### Data acquisition
- Archive intervals that contained 17 March 1997 (and any other day whose HAPI answer starts with a sample from the evening before) failed with a 500: the WIND SWE response for 17 March begins with a spectrum at 16 March 23:58, so that minute was in two day files and merging the field and plasma data stopped with a pandas index error. Each day file is now cut to its own day, and duplicate minutes from files cached earlier are dropped. Found while scanning two years of WIND data for magnetic clouds.
- 7-day DSCOVR and ACE views: the RTSW minutes inside the archive's last 5-minute bin were averaged into that bin together with the archive value, so the last archive point mixed two data sets (e.g. 380 km/s from CDAWeb and four RTSW minutes near 560 km/s gave 526 km/s). RTSW now starts at the first bin after the archive's last one. Found by a new test of the archive/RTSW join.
- Solar cycle panel: the "smoothed sunspot number", F10.7, cycle 25 peak ("~172") and the cycle 24 curve were an analytic sin² rise / exponential decay curve (cycle 24 as 0.68 times it) presented as the current values and labelled as Hathaway's model; the "polar field reversal underway" card was fixed text. The panel now shows NOAA SWPC's observed monthly and 13-month smoothed sunspot number (SILSO) and F10.7, the observed cycle 25 maximum (smoothed SSN 160.9 in October 2024), cycle 24 from the observed record aligned on its December 2008 minimum, and NOAA's predicted cycle with its range. The analytic curve remains as the offline fallback, labelled MODEL; the polar field card, which had no data behind it, now shows the observed maximum.
- Aditya-L1: checked whether ASPEX/SWIS or MAG Level-2 data can be fetched without a personal login. The ISSDC PRADAN landing page is public, but every data page redirects to the ISSDC sign-in, the PRADAN FAQ says data are available after registering, and CDAWeb has no copy. Aditya-L1 therefore stays a labelled simulation; the mission entry points to PRADAN and the provenance text says that a registered login is required.
- Geomagnetic indices: OMNI 1-min SYM-H, ASY-H, AE, AL and AU (WDC Kyoto) are read from OMNI_HRO_1MIN with the solar wind and carried in OMNI records and exports. ### Scientific corrections
- NOAA G scale: the classifier started G1 at Kp 5.0, so Kp 5- (4.67) was reported as G0, 6- as G1, 8- as G3 and so on. NOAA counts a "minus" value with its integer (G4 is "Kp 8, including a 9-"), and SWPC's own Kp product tags 4.67 as G1. The levels now start at 5-, 6-, 7-, 8- and 9o; the forecast hazard cards use the same levels.
- Physics calculator (sandbox): the bow shock models were fed the proton-only magnetosonic Mach number (V_A = 21.8 B/√N, C_s = 0.117 √T), while the orbit view and the panel text use the OMNI definitions (V_A = 20 B/√N, C_s = 0.12 √(T + 1.28×10⁵)), so the same conditions gave different bow shocks in the two views (the proton value is 10-15% higher); "Send to orbit view" passed the proton value on. The bow shocks and the badge now use the OMNI M_ms (also available as `SpaceWeatherPhysics.omni_magnetosonic_mach`); the wave speed table keeps the proton values, as `/api/physics` does. `/api/physics` computed M_A and M_ms from wave speeds already rounded to 0.1 km/s and differed from the calculator in the second decimal. A new test runs the browser calculator in Node for four regimes and checks every quantity (P_dyn, wave speeds, Mach numbers, β, Shue 1997/1998, Chao and Farris-Russell bow shocks, ε, Newell, Boyle, E_y, AE proxy) against the Python implementation. The AE proxy 0.048 (dΦ/dt)^0.85 + 25 nT was listed under Newell et al. (2007), which does not give it; it is now labelled as a rough HELIOS-L1 scaling, and the duplicate Newell (2007) entry in the reference library is merged.
- Storm forecast tab: the "AI / ML" forecaster had no machine learning in it. Its Kp was an ad hoc blend (0.6 (1.8 + dΦ/dt / 7000) + 0.4 (1 + |Dst|/22)), the "95% CI" band was an invented ±(0.3 + 0.12 h), the G1/G3/G5 storm probabilities were linear ramps of that Kp, the auroral boundary was 68 - 1.9 Kp, the satellite card quoted an invented drag multiplier (1 + 0.45 (Kp - 3)), the aviation card announced polar cap absorption from Kp (it needs a solar proton event) and the Newell coupling was given in Wb/s (its units are (km/s)^4/3 nT^2/3). Kp now comes from the Newell et al. (2008) solar wind fit, Kp = 0.05 + 2.244×10⁻⁴ dΦ/dt + 2.844×10⁻⁶ n^½ v² (coefficients as implemented in JHUAPL's kaipy), the band is the range of that Kp over the last 3 h of data and is labelled so, the boundary is Starkov (1994) for that Kp, and the probabilities are NOAA SWPC's own forecast for the next UTC day (minor G1, moderate G2, strong-extreme G3-G5), with NOAA's predicted 3-hourly Kp drawn on the chart. Without NOAA's forecast the gauges show n/a. The persistence assumption behind the 12-hour trajectory (drivers relaxing to quiet values by 5 % per hour) is listed under the chart. The forecast endpoint answers 503 instead of a forecast built from default values when no record has speed and Bz.
- CME solver presets, checked against the SOHO/LASCO CDAW CME catalogue: "May 2024 (~1800 km/s)" matched none of the CMEs behind the 10 May 2024 storm; it now uses the 9 May 09:24 UT halo CME at its catalogue linear speed of 1280 km/s, the fastest of the 8-9 May CMEs that merged on the way. "Halloween 2003 (~2150 km/s)" is now the 28 October 11:30 UT halo at 2459 km/s, and Bastille Day gives the catalogue 1674 km/s exactly (it gave 1675). Carrington 1859 and Nominal are marked illustrative (there are no coronagraph data for 1859), and each button's tooltip names the catalogue entry. The shock Mach number and the Kp category of the solver stay as labelled rough estimates: no published relation gives either from a plane-of-sky speed alone.
- Hemispheric power: the auroral tab, map overlay and reports gave 10^(0.21 Kp + 0.5) GW, a relation with no source (5.1 GW at Kp 1, 245 GW at Kp 9). It is now the Zhang & Paxton (2008) TIMED/GUVI relation HP = 16.82 exp(0.32 Kp) - 4.86 GW up to Kp 7, with the linear ramp to 300 GW at Kp 9 that TIE-GCM and WACCM use above Kp 7 (checked against Smith-Johnsen et al. 2018, JGR, eq. 1-2, and `hp_from_kp` in the TIE-GCM source): 18.3 GW at Kp 1, 153 GW at Kp 7. `/api/aurora` returns the relation in `hemispheric_power_source`, and the reference library lists the paper. Before the first answer from the server the auroral map overlay showed Kp 3.5, 42 GW and a boundary latitude from an ad hoc formula; it now shows n/a.
- CME solver: the value labelled "Gopalswamy et al. (2001) transit" was the Sun-L1 distance divided by a mean speed of (u + 400)/2 km/s with a 10-hour floor. The published empirical arrival model is now implemented: effective acceleration a = 2.193 - 0.0054 u m/s² until 0.76 AU, constant speed afterwards (Gopalswamy et al. 2001 abstract via Crossref; acceleration from Ravishankar & Michalek 2019, arXiv:1910.02797). It reproduces the ~4.3-day arrival of slow CMEs the paper reports. The panel shows its 1 AU arrival time and speed next to the drag-based model, whose ambient wind and drag parameter can now be set (they were fixed at 420 km/s and 1×10⁻⁷ km⁻¹, and the propagation animation used 1.8×10⁻⁷ km⁻¹ and ignored the server's wind speed). The panel text credited the drag deceleration to Gopalswamy; it now names Vršnak et al. (2013). The benchmark presets gave other speeds than their labels ("May 2024 (~1800 km/s)" computed 2824 km/s, "Bastille Day (~1675 km/s)" 2128 km/s); their Δt now gives the labelled speed. The response lists the solver's assumptions (no projection correction, rough shock Mach number, Kp category from speed only). The reference entry has the paper's real title and the cessation distance.
- Auroral oval: the Starkov (1994) model replaces the linear Kp/Bz approximation. The poleward and equatorward boundaries of the oval and the equatorward edge of the diffuse aurora are computed in corrected geomagnetic latitude from |AL| and magnetic local time with Starkov's coefficients, read from the page image of Sigernes et al. (2011, Table 2) and identical, signs included, to the copy in the open `auroraloval` package; the boundaries agree with the published Feldstein-Starkov oval plots (UNIS thesis, Fig. 2.10) to the 1.5° they can be read. The driver is the OMNI 1-min AL averaged over the hour before the oval time when OMNI covers it, otherwise Kp converted with Starkov's |AL| = 18 - 12.3 Kp + 27.2 Kp² - 2 Kp³ nT, or a value you enter. |AL| is limited to 18-750 nT: above about 780 nT the fitted equatorward boundary crosses the poleward one. Bz no longer moves the boundaries (the model does not use it). Typical values change: at Kp 7 the equatorward midnight boundary is 59.9° CGM (was below 52°). The map draws both boundaries and the diffuse edge from the server for the oval time, placed with the IGRF-14 centred dipole and the magnetic local time of the subsolar point (it drew a Kp ring around a fixed pole); the cursor and station MLT use the same dipole (the old MLT was about 3.5 h off at Tromsø). The aurora tab has oval time and AL inputs, shows the AL used and its source, and `/api/aurora` takes `time` and `al`; for a past time without OMNI AL, Kp or AL it answers 404 instead of drawing today's oval. The hemispheric power card says it is a Kp estimate.
- Ring current (Dst) models. The model labelled "Burton" combined O'Brien & McPherron's (2000) injection with Burton's fixed 7.7 h decay. Both published models are now implemented separately and selectable: O'Brien & McPherron (2000), Q = -4.4(VBs - 0.49) nT/h, τ = 2.4 exp(9.74/(4.69 + VBs)) h, b = 7.26 nT/nPa^½, c = 11 nT (default), and Burton et al. (1975), Q = -1.5e-3 nT s⁻¹ per mV/m above 0.5 mV/m, decay 3.6e-5 s⁻¹ (7.7 h), b = 0.20 nT (eV cm⁻³)^-½ = 15.8 nT/nPa^½, c = 20 nT. Coefficients were checked against Ji et al. (2012, JGR, NASA NTRS 20140006636), the 2025 Earth and Planetary Physics paper on semi-empirical Dst (epp2025072) and the PREDSTORM code. The forecaster's "current Dst" came from an ad hoc formula (6.5 Bz V/400 - 1.5 P_dyn); it is now the latest observed Kyoto Dst, and the 12-hour trajectory steps the O'Brien-McPherron model from it.
- Bow shock and magnetopause models. The formulas labelled "Chao et al. (2002)" were not that model: the magnetopause used (11.12 + 0.057/0.541 Bz) P^(-1/6.6) with a P-linear flaring term, and the bow shock (14.5 + 0.08 Bz) P^(-1/6.6) times an ad hoc Mach factor, with clamps. The bow shock now uses the published Chao et al. (2002) model, r = r0((1 + ε)/(1 + ε cos θ))^α with ε = 1.029 and r0, α depending on P_dyn, Bz, plasma β and the magnetosonic Mach number M_ms (14 coefficients). The functional form was checked against Zhou et al. (2020, Chin. J. Space Sci.) and Mo et al. (2025, JGR, open access); the implementation reproduces the 13.325 R_E standoff Mo et al. list for the original coefficients. Chao et al.'s magnetopause coefficients are not available in any open source, so the magnetopause is now Shue et al. (1998) in every view. The second option is the Farris & Russell (1994) bow shock on the Shue et al. (1998) magnetopause (the relation OMNI uses for its bow shock nose, checked against the OMNI documentation and Tátrallyay et al. 2012) with the Farris et al. (1991) shape; it replaces a Shue-shaped shock with a fixed α = 0.60. The orbit view's Shue flaring still used ln(P + 1); it now shares the corrected formulas. M_ms and β are computed from the measured speed, density, temperature and |B| with the OMNI definitions; the orbit view had used a fixed Mach number of 8 because telemetry records carry no Mach field, and the sandbox fed the Alfvén Mach number to the bow shock. The sandbox compares Shue (1998) with the Shue (1997) standoff OMNI uses. `/api/magnetosphere/boundaries` takes `plasma_beta`, rejects unknown models and names the magnetopause and bow shock models separately. The Chao et al. (2002) DOI in the reference library was wrong (now 10.1016/S0964-2749(02)80212-8).
- Akasofu ε lacked the 4π/μ₀ factor of the SI form and was 12.6 times too small (500 km/s, 10 nT southward: 994 GW, previously 79 GW).
- Shue et al. (1998) flaring exponent used ln(P_dyn + 1) instead of ln(P_dyn) (API and in-browser calculator).
- Flare class is the real GOES class (e.g. X5.3); before, it was the R-scale threshold label ("X1" for an X5.3 flare, "B" for A-class). Without proton data the S-scale says so instead of using an invented 0.8 pfu.
- Spectrum tab: the sample interval is taken from the time stamps (it was fixed at 60 s, so 5-minute data had all frequencies 5× too high); gaps are interpolated instead of spliced out; the PSD is one-sided and window-normalised in (unit)²/Hz.
- Dst (Burton/O'Brien–McPherron) simulation used a fixed 5-minute step, so 1-minute data ran five times too fast. The step now comes from the time stamps and uses the exact solution over each step.
- The comparator's spatial baseline and theoretical delay use the measured position (NOAA RTSW hourly ephemeris) of the spacecraft that actually supplied observed RTSW data, e.g. SOLAR1 for the operational "DSCOVR" stream, instead of the mission's model orbit. On live data for SOLAR1 vs ACE (173,000 km apart along X) the theoretical delay (10.0 min) and the cross-correlation lag (10 min) agree. The position source is reported for each side.
- Cross-correlation lag had the opposite sign to the theoretical propagation delay it is compared with. Positive now means spacecraft B observes later than A.
- Comparator no longer bridges long data gaps with interpolated values that were then counted as real samples; mixed time zone formats can be compared.
- A single interplanetary shock was reported up to three times; it is now one event.
- GSE Z axis in the ephemeris engine pointed to ecliptic south (left-handed frame), flipping the sign of every GSE z. Orbit trajectories returned the same point for every step.
- Boyle et al. (1997) polar cap potential uses the IMF magnitude |B| (it used √(By² + Bz²)).
- Newell coupling in the forecaster used |B| instead of the transverse field B_T = √(By² + Bz²).
- D-RAP absorption follows the SWPC relation HAF = 10 log₁₀(Fx) + 65 MHz (reduced by cos^0.75 χ) and A(f) = (HAF/f)^1.5 dB.
